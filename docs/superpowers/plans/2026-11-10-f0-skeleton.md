# F0: Skeleton, sign-in and deploy Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A page that loads behind Google sign-in at the owner's web address, served from his VPS, with Postgres, tests and deploy in place.

**Architecture:** A FastAPI app built by `create_app(settings)`. `oauth2-proxy` sits in front and passes the signed-in email in a header; the app looks that email up in `users`. Postgres holds `users` and a migrations ledger. One Docker Compose project behind the VPS's existing Traefik.

**Tech Stack:** Python 3.12, FastAPI, Uvicorn, Jinja2, psycopg 3 (with pool), pydantic-settings, pytest, ruff, Docker Compose, oauth2-proxy, Postgres 17, GitHub Actions.

**Spec:** `.10x/specs/2026-11-10-pubmedgemini-quick-design.md` (§4, §8, §9 F0, §13, §14). ADR: `.10x/adrs/001-single-vps-python-gemini-flash-lite.md`.

## Global Constraints

- Python 3.12. Package name `pubmedgemini`, source in `src/pubmedgemini/`.
- No secret is ever in the repo, an image or a log. `.env` is git-ignored; `.env.example` holds names only.
- Logs hold counts and fixed kinds only. Never email addresses in full, question text or model replies. (Emails are logged as a count or omitted.)
- Only `gate` is reachable from outside. `app` and `db` publish no ports.
- Postgres 17. SQL changes are numbered files in `migrations/`, applied in order at start-up.
- `ruff check` and `pytest` pass before every commit.
- F0 contains no Gemini and no PubMed code.
- Work on branch `f0-skeleton`. Open a pull request. Do not merge without the owner's explicit "merge it".
- Message when a signed-in user is not in `users` (exact): "Your Google account is allowed in, but you haven't been set up yet. Ask the owner to add you."

## Review Focus

1. A request reaches the app with no email header (gate misconfigured): the app answers 401 with a plain page, never a default user.
2. `X-Dev-User-Email` is sent in production: it is ignored.
3. The allowed email differs only in letter case or surrounding spaces (`Owner@Gmail.com `): it matches.
4. Postgres is down when a page is requested: a plain 503 page, no stack trace, and `/healthz` reports unhealthy.
5. The app starts twice against the same database: migrations are not applied twice and start-up does not fail.

Each has a test in the task that owns the code (Tasks 2, 3 and 4).

### Task 2: Database pool and migrations

**Files:**
- Create: `src/pubmedgemini/db.py`, `src/pubmedgemini/migrate.py`, `migrations/0001_users.sql`, `tests/conftest.py`
- Test: `tests/test_migrate.py`, `tests/test_db.py`

**Interfaces:**
- Consumes: `Settings.database_url`, `Settings.migrations_dir`.
- Produces: `open_pool(database_url: str) -> psycopg_pool.ConnectionPool`; `is_healthy(pool) -> bool` (runs `SELECT 1`, returns `False` on any database error, never raises); `apply_migrations(pool, migrations_dir: Path) -> list[str]` (returns the file names applied in this call).
- `conftest.py` produces fixtures `pool` (a pool on `TEST_DATABASE_URL`, with the schema dropped and recreated before each test) and skips database tests with a clear message when `TEST_DATABASE_URL` is unset.

`migrations/0001_users.sql`:

```sql
CREATE TABLE users (
    id         BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    email      TEXT NOT NULL UNIQUE CHECK (email = lower(btrim(email))),
    role       TEXT NOT NULL CHECK (role IN ('owner', 'surgeon', 'fellow')),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

Migration rules: files match `NNNN_name.sql`; applied in name order; each file and its ledger row (`schema_migrations(name TEXT PRIMARY KEY, applied_at TIMESTAMPTZ)`) go in one transaction; a session advisory lock (`pg_advisory_lock(7310)`) is held for the whole call so two starting apps cannot both apply.

**Files:**
- Create: `src/pubmedgemini/main.py`, `src/pubmedgemini/web.py`, `src/pubmedgemini/templates/base.html`, `home.html`, `message.html`
- Test: `tests/test_web.py`, `tests/test_logging.py`

**Interfaces:**
- Consumes: everything from Tasks 1–3.
- Produces: `create_app(settings: Settings) -> FastAPI`. On start-up: open the pool, `apply_migrations`, `ensure_owner`; if the database is unreachable at start-up, log one line (`kind=db_unreachable`) and keep serving, retrying the start-up work on the next request that needs the database. On shutdown: close the pool. `main.py` also exposes `app = create_app(load_settings())` behind `if`-free module import for Uvicorn (`pubmedgemini.main:app`).

Routes:

| Route | Signed in and set up | Otherwise |
|---|---|---|
| `GET /` | 200, `home.html`: heading "pubmedgemini", the line "Signed in as <email>", the line "Search and answers arrive in the next stages." | `NotSignedIn` → 401 `message.html` "You are not signed in."; `NotSetUp` → 403 `message.html` with the exact message in Global Constraints |
| `GET /healthz` | No sign-in needed. 200 `{"status":"ok"}` when `is_healthy`; 503 `{"status":"database_unreachable"}` otherwise | |

Any database error while handling a page → 503 `message.html` "The database could not be reached. Please try again in a minute." No stack trace in the body.

Pages are plain HTML: one `<main>`, system font, max width 42rem, no JavaScript, no external assets.

### Task 5: Container, Compose and backup

**Files:**
- Create: `Dockerfile`, `compose.yaml`, `.env.example`, `.dockerignore`, `infra/backup.sh`
- Test: `tests/test_compose.py`

**Interfaces:**
- Consumes: `pubmedgemini.main:app`, `/healthz`.
- Produces: image entrypoint `uvicorn pubmedgemini.main:app --host 0.0.0.0 --port 8000 --no-access-log`; Compose services `gate`, `app`, `db`.

`compose.yaml` decisions:

- `db`: `postgres:17`, volume `pgdata`, env `POSTGRES_PASSWORD` from `.env`, healthcheck `pg_isready`, **no `ports`**, network `internal` only.
- `app`: image `${APP_IMAGE}`, env `APP_ENV=prod`, `DATABASE_URL`, `OWNER_EMAIL`, depends on `db` healthy, healthcheck on `/healthz`, **no `ports`**, network `internal` only, runs as a non-root user, `restart: unless-stopped`.
- `gate`: `quay.io/oauth2-proxy/oauth2-proxy` pinned to a version tag, networks `internal` and the external Traefik network `${TRAEFIK_NETWORK}`, **no `ports`**. Settings: provider `google`; `--upstream=http://app:8000`; `--http-address=0.0.0.0:4180`; `--authenticated-emails-file=/etc/gate/emails.txt` (mounted read-only from `./gate/emails.txt` on the VPS, git-ignored); `--pass-user-headers=true` (sends `X-Forwarded-Email`); `--skip-auth-route=GET=^/healthz$`; `--cookie-secure=true`; `--reverse-proxy=true`; client ID, client secret and cookie secret from `.env`; `--redirect-url=https://${APP_HOST}/oauth2/callback`.
- Traefik labels on `gate` only, all names from `.env`: router rule ``Host(`${APP_HOST}`)``, entrypoint `${TRAEFIK_ENTRYPOINT}`, cert resolver `${TRAEFIK_CERTRESOLVER}`, service port 4180.

`.env.example` (names only, no values): `APP_IMAGE`, `APP_HOST`, `OWNER_EMAIL`, `POSTGRES_PASSWORD`, `DATABASE_URL`, `OAUTH2_PROXY_CLIENT_ID`, `OAUTH2_PROXY_CLIENT_SECRET`, `OAUTH2_PROXY_COOKIE_SECRET`, `TRAEFIK_NETWORK`, `TRAEFIK_ENTRYPOINT`, `TRAEFIK_CERTRESOLVER`.

`infra/backup.sh`: `docker compose exec -T db pg_dump -U postgres -Fc postgres` into `/var/backups/pubmedgemini/YYYY-MM-DD.dump`, then delete dumps older than 7 days. Exits non-zero if the dump is empty.

### Task 6: CI and deploy

**Files:**
- Create: `.github/workflows/ci.yml`, `.github/workflows/deploy.yml`

**Interfaces:**
- Consumes: the test suite; `compose.yaml` on the VPS at `/opt/pubmedgemini`.

On failure it restores the previous `APP_IMAGE` line and runs `docker compose up -d` again.
- The repo's copy of `compose.yaml` is copied to the VPS in the same SSH step, so the stack definition always matches `main`.

### Task 7: VPS runbook

**Files:**
- Create: `infra/README.md`
- Modify: `README.md` (add how to run tests locally and a link to the runbook)

One-time setup, written as numbered steps of one command each, for the owner to run as given. No secret value appears in the file.

1. Point the web address at the VPS (an A record to its IPv4 address).
2. Read the VPS's Traefik names: one command that prints the entrypoint, cert resolver and Docker network from the existing Traefik Compose file; the three values go into `.env`.
3. Create `/opt/pubmedgemini`, `gate/emails.txt` (one allowed Google address per line) and `.env` from `.env.example`, mode 600, owned by root. `OAUTH2_PROXY_COOKIE_SECRET` and `POSTGRES_PASSWORD` are generated on the VPS with `openssl rand`.
4. Create the Google sign-in client (Google Cloud console → OAuth client, type "Web application", redirect URI `https://<APP_HOST>/oauth2/callback`); type the ID and secret into `.env` on the VPS.
5. Create a deploy-only SSH key pair; public half into the VPS user's `authorized_keys`, private half into the GitHub secret `VPS_SSH_KEY`; record the host key in `VPS_KNOWN_HOSTS`.
6. Let the VPS pull the image: `docker login ghcr.io` with a token that can only read packages.
7. Turn on a firewall that allows only ports 22, 80 and 443.
8. Install the nightly backup: one `cron` line running `infra/backup.sh` at 02:30 IST.
9. Check: open `https://<APP_HOST>`; sign in; see "Signed in as …". Sign in with an address not on the list; see Google's sign-in refuse it.

Also documents rollback (set `APP_IMAGE` to the previous tag, `docker compose up -d`) and restore from a dump.
