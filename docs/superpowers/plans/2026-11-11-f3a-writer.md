# F3a: the writer in four parts, the citation check and the stored answer (Implementation Plan)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task by task. Steps use checkbox (`- [ ]`) syntax.

**Goal:** After the study list, Gemini Flash-Lite writes Incisive Quick's answer (AnswerV3) in four parts at once, with Incisive's prompts word for word. Code merges the parts, falls back to one piece when a part fails twice, builds the references, runs Incisive's citation check, and stores the answer. The existing run page shows it as plain headings and paragraphs, in the grey look. No new layout, no script, no Introduction, no number check (F3b, F4).

**Architecture:** A new package `src/pubmedgemini/writer/` ports Incisive's `writer_v3.rs` Quick parts: `prompts.py` (input, prompts), `read.py` (`into_answer`), `answer.py` (AnswerV3, citation check), `parts.py` (four parts on threads, all through the one `ModelCaller`, pacer and cap). The runner keeps the fetched records, gates on time, writes, checks citations and stores answer and status in one transaction. Migration 0005 adds `answers` and the step kinds.

**Spec:** `.10x/specs/2026-11-10-pubmedgemini-quick-design.md` §2a, §4, §5, §7, §8, §9 F3. Reference code (read-only): Incisive at commit `12630f7`, under `crates/incisive-app/src/`: `agent/team.rs`, `agent/writer_v3.rs`, `agent/answer_v3.rs`, `agent/llm.rs`, `run_tracker.rs`, `runs/mod.rs`. Below, `w.rs:N` means `agent/writer_v3.rs` line N, `t.rs:N` means `agent/team.rs`, `a.rs:N` means `agent/answer_v3.rs`. All Fact, read by the Architect on 11 Nov 2026, unless marked.

**Work on branch** `f3a-writer` from `main` (`9e20c7d`). Merging deploys. Do not merge without the owner's "merge it".

## Global constraints

- Everything in F0, F1 and F2's Global Constraints still holds.
- **Never logged:** question, studies, abstracts, model text, Google's message. Writer lines hold part names, kinds and counts only.
- **Prompts word for word.** `SYSTEM`, the user message, the part instruction, the submit line and `SCHEMA_NUDGE` are Incisive's. The only changes for Gemini: schemas go through `to_openapi`; the retry's `effort: low` is dropped (D7).

## Where the code disagreed with the notes

1. Runs left: the code's formula gives 21, not "about 31" (above).
2. `model_calls.step` allows only the four researcher steps (`migrations/0003_model_calls.sql:14-15`). A writer attempt's `record_attempt` would fail and end the run `internal`. Not in the notes; fixed in Task 1.
3. `runs.add_step` takes the next `seq` with `MAX(seq)+1` and no lock (`runs.py:266-278`). Four threads writing lines (the waiting line, F3b's early store) can collide on the primary key and lose a line. Not in the notes; fixed in Task 1.
4. `tests/gemini_fakes.py` `FakeGemini` serves a script in order with no lock: four threads would get replies in any order. Task 6 adds a routed fake.
5. The fetch-gap line is `{n} selected study could not be fetched from PubMed and was left out` in the singular (`t.rs:428-447`); the notes gave only the plural.
6. The F2 word-for-word test compares against strings typed out from the Rust source; it does not read the Rust file. Task 3 adds a script that does.
7. The probe's writer part is "outcomes" (`probes/flash_lite_probe.py` `stage_d`); the notes left it open.
8. Incisive's schema keys are alphabetical (no `preserve_order` in any workspace `Cargo.toml`: Fact; via a dependency: Not checked). The port keeps that order and sends no `propertyOrdering`.

### Task 6: The writer run: four parts, retry, merge, fallback

**Files:** Create `src/pubmedgemini/writer/parts.py`, `tests/writer_fakes.py`. Test `tests/test_writer_parts.py`.

**Interfaces:**
- `WriteFailure = Literal["truncated", "unreadable"]`; `class WriterFailed(Exception)` with `.failure: WriteFailure | None` and `.kind: str | None` (a GeminiError kind).
- `PartEvent`: `("summary", wire_summary) | ("context", wire_context) | ("withdraw", None)`.
- `write_parts(user, *, caller, run_id, timing, on_wait, on_part: Callable[[PartEvent], None] | None = None, clock) -> tuple[WrittenAnswer, int, bool]` (answer, labels defaulted, merged). Port of `w.rs:2145-2310`.
- `write_one_piece(user, *, caller, run_id, timing, on_wait, clock) -> tuple[WrittenAnswer, int]`. Port of `w.rs:1614-1670`.
- One part (`section_reply`, `w.rs:2075-2123`): `structured_body(with_source_rule(SYSTEM), section_user(user, s), section_schema(s), s.max_tokens(WRITER_MAX_TOKENS))`, `step="writer_<name>"`, `deadline=attempt_deadline=timing.hard_stop_at`. Cut off or unreadable (or refused: Q3) → **one** retry with `user + SCHEMA_NUDGE`, `step="writer_<name>_retry"`, same schema and cap (D7). A non-fatal `GeminiError` after the caller's own attempts → that part failed (Incisive `StepError::Llm`, not fatal).
- Threads: `concurrent.futures.ThreadPoolExecutor(max_workers=4, thread_name_prefix="writer")`, all four submitted at once; wait for all four (a failure never cancels the others).
- **Fatal, propagated at once after all four are in:** `HardStop` (any part's `DeadlineReached`, or the clock past `hard_stop_at`), `RunCapReached`, a GeminiError kind in `FATAL_KINDS` (Q2).
- Events (`w.rs:2160-2283`): context and summary reported when read; the first part to fail for good sends `withdraw`; under one lock, nothing reported after `withdraw`; a callback error is logged by kind and ignored.
- All four read → `merge_sections` → `into_answer`, `merged=True`.
- Any part failed → if `hard_stop_at − now < WRITER_MIN_SECONDS` (150): raise `WriterFailed` with the **first failed part's** failure in `Section` order.
